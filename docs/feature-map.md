# Dashboard feature map

Every page and feature of the dashboard, how a person reaches it, and how a
script finds it. `scripts/dev/control-dashboard.mjs` reads this file: `open
<page>` takes a page id from the first table, and `check` opens every page in
it. `test/feature-map.test.ts` fails when a route, page file, sidebar row,
shortcut or `data-testid` in `web/src/` is missing here, or when this file
names one that no longer exists. Change the map in the same commit as the UI.

Selectors are `[data-testid="…"]`. A page is open once its **Root** element
is there and its heading (`[data-testid="page-title"]`, inside
`main header`) contains the **Ready when** text. `<n>` is an issue number,
`<id>` a run id, `<decision>` a decision's id (or `pr-<number>` for a PR held for a person).

Any other path shows the Board, the dashboard's home.

**Sidebar groups (#585).** The sidebar lists groups: Needs you, Work, Overview, Shipping, Agents, Extend,
Experiments, Machine and Settings. A grouped page is a tab under its group (Sidebar `Group › Tab`; a group's first
tab shares its name or is what the group's row opens) and keeps its `g` key. The old addresses redirect (replace, not
push; an id, the query and the hash kept): `/inbox`, `/waiting`, `/decisions[/<decision>]` to `/needs-you/…`;
`/issues[/<n>]`, `/intake`, `/prs` to `/work/…`; `/land`, `/deploys` to `/shipping/…`; `/activity` to
`/agents/activity`; `/health`, `/logs`, `/reports` to `/machine/…`; `/setup` to `/settings/setup`
(`web/src/redirects.ts`). A group's own address opens it: `/needs-you` is its queue, `/work` opens the Board (`/`) and
`/shipping` the Land queue.
