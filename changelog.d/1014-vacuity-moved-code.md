### Guardrail changes: what each one does

- **Code a PR moves without git pairing it no longer lets a test of the moved code merge the PR (#1014).** Before, a file renamed and re-indented or edited, a function split out into another file or moved within its file, or moved code re-wrapped, read as added code: a test that ran the moved code merged the PR even when its real change was untested.
  - The vacuity gate now also measures each file with every top-level statement the PR moved whole (a function, a class, a declaration) measured against its source, from any app file at the base, a deleted one included. It pairs a statement first by its code (whitespace, parentheses, commas and semicolons left out), then by its declared name. A file counts only where it counts both ways, so the pairing only ever takes measure away: a dead copy of an edited line's old text still never makes the edit count.
  - Lines swapped inside a function that stays are not a move: reordering is a change, and a test that runs it counts as before.
  - **Limit:** a statement renamed as it moved, or moved inside one that stays (a method within its class, a statement into another function), still reads as added code.
