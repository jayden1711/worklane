### Upgrading (from v0.5.2)

- **A changed path that looks like a locked or protected one now waits for the owner (#763).** A PR that adds a sibling like `docs/releasing.md` spelled with a Cyrillic e, beside the locked `docs/releasing.md`, came out L0 and could merge itself; it is now L3 and waits, with the reason `path that looks like a protected one: ... (like docs/releasing.md (...))`, the path in it escaped. Every text that shows a changed path through the shared path display (level reasons, high-risk and "Waiting on you" lines, hold comments, the plan comment's file list, the event summary of a frozen reproduction test) now shows it escaped (`\uXXXX`, JSON-quoted), as it already did for invisible characters, when it holds any character outside ASCII other than an accent on an ASCII letter (a letter of another script, a fullwidth letter, the Kelvin or Angstrom sign, a lone combining mark, a no-break space, the braille blank), or a space at the start or end of a name. An ASCII-only look-alike (`rn` for `m`) can't be escaped; its reason quotes it and says what it looks like. So a name in another script (`docs/` and a Japanese name, say) now shows escaped too. Accented names (`docs/naïve.md`) still show as themselves. Review levels are unchanged for accented names and for other-script names that look like no protected path.
- **Money paths are globs only (#763).** A `/regex/flags` line in the `money_path_source` list is now read as a glob. After upgrading, a held PR's reason names each line that needs rewriting.
  - **Converted:** a line whose regex has a mechanical glob form becomes that glob and keeps its money protection. The mechanical forms are literal text, escaped punctuation, `.*` as `**`, `[^/]*` as `*`, `[^/]+`, `[^/]` and the `^`/`$` anchors (`/^src\/payments\//` becomes `src/payments/**`).
  - **Refused:** any other line is refused, never dropped. That covers the `i` flag, a class, `\d`, `|`, groups and quantified letters. Until the list is fixed, every path counts as a money path, and every PR waits with a reason that names the line and suggests a glob.
  - **Which lines are regexes:** a line is a regex only when it is a `/.../flags` token. So a glob line such as `src/payments/**` is now read as the glob it is, and the glob lines after a regex line are read too.
  - **Nothing stops counting:** every `/.../` that earlier versions found in the text, such as the `/payments/` inside `src/payments/**`, is still read and converted, so no path that counted as a money path before stops counting.
  - Globs are case-sensitive, so list each spelling you need.

### Guardrail changes: what each one does

- **`confusable-path` (new, always L3, never loosened, #763):** a changed path whose Unicode confusable skeleton (UTS #39, from Unicode 17.0.0's `confusables.txt`, shipped as a generated table with the file's version and sha256 recorded) matches a glob of a category that waits for a person (the locked ones, `review.yaml`'s L3 and `merge.wait_categories`, ci-config) or a money path, while the path itself doesn't. Money paths are globs (see Upgrading), compared like any other glob. Globs are matched in linear time, and one change's look-alike work has a budget; paths past it wait as not compared. A glob's `?` stands for an m spelled r, n. A combining dot above that an i's own dot hides is dropped. Covers ASCII look-alikes too (`rn` for `m`, `1` or `I` for `l`, `O` for `0`). An ASCII path is compared with its case as written. Also, for a name outside ASCII, a case-insensitive match (a long s) and its NFKC form's (a fullwidth letter); and a name with a blank-looking character (a trailing space, a no-break space, the braille blank) read without it. A path over 1,024 characters, or whose skeleton is over 4,096, isn't compared and waits.
