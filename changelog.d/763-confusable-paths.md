### Upgrading (from v0.5.2)

- **A changed path that looks like a locked or protected one now waits for the owner (#763).** A PR that adds a sibling like `docs/releasing.md` spelled with a Cyrillic e, beside the locked `docs/releasing.md`, came out L0 and could merge itself; it is now L3 and waits, with the reason `path that looks like a protected one: ... (like docs/releasing.md (...))`, the path in it escaped. Reasons, events and comments now show a path escaped (`\uXXXX`, JSON-quoted), as they already did for invisible characters, when it holds any character outside ASCII other than an accent on an ASCII letter (a letter of another script, a fullwidth letter, a no-break space, the braille blank), or a space at the start or end of a name: so a name in another script (`docs/` and a Japanese name, say) now shows escaped too. Accented names (`docs/naïve.md`) still show as themselves. Review levels are unchanged for accented names and for other-script names that look like no protected path.

### Guardrail changes: what each one does

- **`confusable-path` (new, always L3, never loosened, #763):** a changed path whose Unicode confusable skeleton (UTS #39, from Unicode 17.0.0's `confusables.txt`, shipped as a generated table with the file's version and sha256 recorded) matches a glob of a category that waits for a person (the locked ones, `review.yaml`'s L3 and `merge.wait_categories`, ci-config) or a money path, while the path itself doesn't. Covers ASCII look-alikes too (`rn` for `m`, `1` for `l`); for a name outside ASCII a case-insensitive match (a long s) and its NFKC form's (a fullwidth letter); and a name with a blank-looking character (a trailing space, a no-break space, the braille blank) read without it. A path over 1,024 characters, or whose skeleton is over 4,096, isn't compared and waits.
