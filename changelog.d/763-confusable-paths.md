### Upgrading (from v0.5.2)

- **A changed path that looks like a locked or protected one now waits for the owner (#763).** A PR that adds a sibling like `docs/releasing.md` spelled with a Cyrillic e, beside the locked `docs/releasing.md`, came out L0 and could merge itself; it is now L3 and waits, with the reason `path that looks like a protected one: ... (like docs/releasing.md (...))`, the path in it escaped. Every text that shows a changed path through the shared path display (level reasons, high-risk and "Waiting on you" lines, hold comments, the plan comment's file list, the event summary of a frozen reproduction test) now shows it escaped (`\uXXXX`, JSON-quoted), as it already did for invisible characters, when it holds any character outside ASCII other than an accent on an ASCII letter (a letter of another script, a fullwidth letter, the Kelvin or Angstrom sign, the capital I with a dot above, a lone combining mark, a no-break space, the braille blank), or a space at the start or end of a name. An ASCII-only look-alike (`rn` for `m`) can't be escaped; its reason quotes it and says what it looks like. So a name in another script (`docs/` and a Japanese name, say) now shows escaped too. Accented names (`docs/naïve.md`) still show as themselves. Review levels are unchanged for accented names and for other-script names that look like no protected path.
- **Money paths are globs only (#763).** A `/regex/flags` line in the `money_path_source` list is now read as a glob. After upgrading, a held PR's reason names each line that needs rewriting.
  - **Converted:** a line whose regex has a mechanical glob form becomes that glob and keeps its money protection. The mechanical forms are literal text, escaped punctuation, `.*` as `**`, `[^/]*` as `*`, `[^/]+`, `[^/]` and the `^`/`$` anchors (`/^src\/payments\//` becomes `src/payments/**`).
  - **Refused:** any other regex line is refused, never dropped. That covers the `i` flag, a class, `\d`, `|`, groups and quantified letters, and a regex that isn't valid. Until the list is fixed, every path counts as a money path, and every PR waits with a reason that names the line and suggests a glob; `doctor` fails a `money paths` check naming each line.
  - **Which lines are regexes:** a line is a regex only when it is a `/.../flags` token, read as JS reads a regex literal (a `/` inside `[...]` doesn't end it). So a glob line such as `src/payments/**` or `src/**/billing/**` is read as the glob it is, never refused for its slashes, and the glob lines after a regex line are read too.
  - **Glob lines read literally are refused too:** a glob line with a brace set (`{a,b}`), a `[...]` class, an extglob (`@(...)`), a leading `!` or list marker (`- `), a quote or a backslash used to match nothing, silently (this glob dialect reads those characters literally), and so did one no git path can match as written (a leading `/`, a `//`, a trailing `,` or `;`). It is now refused the same way, with a suggested glob, so an install with such a line has every PR held until the line is fixed, and `doctor` names it. A trailing ` # comment` or ` // comment`, and quotes around the whole glob, are taken off instead.
  - **What earlier versions counted still counts:** earlier versions' own reading of the list (every `/.../` they found in it, such as `/payments/` inside `src/payments/**`, and each line they read as a glob) is kept for money-path membership, so no path that counted as a money path before stops counting. It isn't compared for look-alikes. And what only this version counts as money still counts as app code for the large-change L2, so no review level drops below what earlier versions gave.
  - **A list that failed to load (the owner's decision):** a list with a glob line holding `/**/` or `/*/` (`src/**/billing/**`) failed to load in earlier versions, which read its `/**/` as a regex. Its globs are now read as written, so such an install gets glob protection.
  - Globs are case-sensitive, so list each spelling you need (a refused `/.../i` line's suggested glob is written in one case).

### Guardrail changes: what each one does

- **`confusable-path` (new, always L3, never loosened, #763):** a changed path whose Unicode confusable skeleton (UTS #39, from Unicode 17.0.0's `confusables.txt`, shipped as a generated table with the file's version and sha256 recorded) matches a glob of a category that waits for a person (the locked ones, `review.yaml`'s L3 and `merge.wait_categories`, ci-config) or a money path, while the path itself doesn't. Money paths are globs (see Upgrading), compared like any other glob. Globs are matched in linear time, and one change's look-alike work has a budget, charged per comparison, per character walked and per character each pass of a form reads and makes; paths past it wait as not compared. A glob's `?` stands for an m spelled r, n. A combining dot above that an i's own dot hides is dropped. Covers ASCII look-alikes too (`rn` for `m`, `1` or `I` for `l`, `O` for `0`). An ASCII path is compared with its case as written. Also, for a name outside ASCII, a case-insensitive match (a long s; case folded before the skeleton and after it, so a capital I standing in for an l counts) and its NFKC form's (a fullwidth letter); and a name with a blank-looking character (a trailing space, a no-break space, the braille blank) read without it. A path over 1,024 characters, one with a run of more than 30 combining marks, or one whose forms grow over 4,096 characters, isn't compared and waits.
