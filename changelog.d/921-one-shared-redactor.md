### Upgrading (from v0.5.2)

- **Dashboard keys now start with `wld_` (#889).** A new key is `wld_` and 32 random characters, a shape the redactor finds wherever it appears. A key from before keeps working until you rotate it. `doctor` warns on each older key it can read (the local dashboard's, each instance's and the hub's) and says how to rotate it: remove the key file and restart what serves that dashboard. On a server with the hub, then run `scripts/setup/dashboards.sh` as root so the hub can read the new key.

### Guardrail changes: what each one does

- **One shared list of token shapes (#889).** The engine's redactor (`src/events/redact.ts`) now knows a Discord bot token, a Tailscale key, a dashboard key and an HTTP Basic credential. A shape with a distinctive prefix (`ghp_`, `github_pat_`, `sk-ant-`, `xoxb-`, `lin_api_`, `AKIA`, `AIza`, `eyJ`, `wld_`, ...) is found wherever its prefix is, whatever is glued before it. The other shapes (a Discord bot token, a Bearer or Basic credential in any case, a Stripe key, a plain `sk-` key) are found after a name glued with `_`, an escape sequence (ESC as a byte, as `\u001b`, `\x1b`, `\033`, `\e` or `^[`, and the 8-bit CSI) or a JSON escape (`\n`). Before, Discord and Tailscale were each redacted only by one module of their own, so a Discord bot token passed through to the event log, issue comments, chat notices and the dashboard's service log.
- **A private key fails closed.** A key's BEGIN line with no END after it is redacted to the end of the text, and an END line with no BEGIN before it from the start, so a key cut short, still being written, or begun above a log window is not shown. This covers PEM keys (upper-case BEGIN and END lines with five dashes) and PGP's private key block. Not covered: a key whose BEGIN and END are both outside a window (only its middle lines in view), and other formats (an ssh.com SSH2 key, a lower-case PEM line, a PuTTY `.ppk` file).
- **The rules no longer run one after another.** Every rule reads the text as it was, and each run of what they find is replaced once, so one rule's match can't take in the text another rule starts from. Before, a dashboard key, a JWT, a Slack or Tailscale token or a bearer value written right before a URL with a password, a bearer token or a Linear key could hide it from the next rule (`wld_<key>-redis://app:<password>@…`). A JWT is found in any dotted part of a run (`sess_0123456789.<jwt>`), an unsigned one (`alg: none`) too. An HTTP Basic value is found whatever is glued after it, and a short one too (base64 of a short `user:password`). A password in a URL is found whatever the scheme's length. Where one rule's find covers the others, it shows that rule's marker (a bearer token that is an `sk-` key now shows as `Bearer [REDACTED]`); where finds only overlap, the run shows `[REDACTED]`. A test holds the default mode to the previous release's rules on composed input.
- **No module keeps its own token rules.** The GitHub sign-in relay, the bench and the root updater now redact through the shared redactor. Its broad mode runs every rule on the text as it was and masks what any of them finds. That covers everything those modules masked before: a token cut short, a clone URL's user info, a value after a secret's name, and a short bearer token. A test compares each with its rules on the previous release, on generated input. The updater is one standalone file, so it carries a generated copy of the redactor, and a test holds that copy to the module.
- **The dashboard's service log** redacts its journal entries and log-file lines as one text, with 100 more above the ones shown, and redacts a long line before cutting it to 2,000 characters. A PR section, a change's diff and a chat attachment are redacted before they are cut, too. Each of these reads only what it keeps plus a margin, so a huge input costs no more than its window. Each window ends at its last whitespace, so a token cut by the window's end is never shown. A text the redactor can't scan (a token prefix followed by a run of millions of characters) becomes `[REDACTED: too large to scan]`, and a chat attachment like that is refused as "text too large to scan" until it is attached anyway. The URL-password rule no longer slows down on a long dotted line.
- A Tailscale key in a Tailscale step line now shows as `tskey-[REDACTED]` (was `[a key]`); the login link is still taken out first, so a token glued before it can't hide it. A test fails on any module that redacts a token shape with its own pattern.
