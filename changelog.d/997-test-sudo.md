### Guardrail changes: what each one does

- **The test suite's tests of setup and machine scripts no longer reach the machine's own sudo or other host tools (#991).** A test that runs a `scripts/` shell script now starts it through one test module, which puts a recording stand-in first on the script's PATH for each host tool the machine has. That covers sudo, systemctl, systemd-run, useradd and the other user tools, visudo, nft, docker, gh, tailscale, claude and the like. Before, `test/add-project.test.ts` ran add-project with the real PATH, and since #904 every fresh run asked the machine's real `sudo -H -u <coordinator>`. A lint test keeps every such test on the module. Its exceptions are pinned and may only shrink: the setup scripts' own CI-only acceptance test, and three CI-only acceptance runs that call the real sudo or visudo on purpose. Nothing changes for an install: only the tests changed.
