### Guardrail changes: what each one does

- **A change that takes a use away from a registered check table waits for the owner (#941).** The weakening hold reads tables from lines. So a PR could add a new table under another name, move every use of the registered table to it, and leave the registered table and its mark unchanged and unused, and the hold saw nothing. Now a removed or changed line, in any changed file, that names a registered table outside the table's own lines makes the change wait. So does a line that names a module-level alias of the table (`const rules = CHECKS`, in that file or imported into it), or a line in the same statement as a use (`const rules =` with `CHECKS;` on the next line). Every registered table counts, also one whose file the change leaves alone. That covers a decoy declared in the same file, one imported from another file, and a use in another file moved to it. So does an added line that declares the table's name (a local copy that shadows it), one that empties or changes it from another file (`CHECKS.splice(0)`), and a re-pointed `package.json` `"imports"` entry. Adding a use, changing lines that never named the table, and another file's own variable of the same name still pass. Part of #941: the shapes the line reader can't see stay open (named in the design notes) until registered tables move to data-only files.
