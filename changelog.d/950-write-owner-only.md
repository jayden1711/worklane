### Upgrading (from v0.5.2)

- **Owner-only files (tokens, keys, settings, state) are never written through a link planted beside them (#950).** The engine wrote each of these files through a temp name anyone could guess, `<file>.<pid>.tmp`, and set its mode by name. A link planted at that name sent the file's data to the link's target, and a link swapped in mid-write had its target's mode set to 0600. Each file is now written to a new file at a random hidden name beside it, `.<name>.<16 hex>.new`, created exclusively without following a link, with its mode set and its data written through that one open file; then it is renamed into place. A staging file found replaced before the rename is refused and removed, and the old file is left as it was. A process killed mid-write may now leave a `.new` file beside the file (0600, this user's), where it used to leave a `.tmp` file.
