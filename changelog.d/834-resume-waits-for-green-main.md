### Upgrading (from v0.5.2)

- **Resuming auto-merge after a red main or the main watch waits for green main (#776).** The dashboard's "Clear and resume auto-merge" (and `POST /api/auto-merge/clear`) on such a stop now records a resume request (`merge.resume_requested`, 202) and reads no check: the coordinator, the only judge, resumes it only when the default branch's required checks all pass on its current tip, read from the remote (`git ls-remote`) and judged by the pinned-source verdict PR readiness and the main watch use (#727: a pinned check from another source counts as missing). It records each measurement (`merge.main_measured`), and the dashboard's answer says the rule and shows the last one made for the stop in force, or that there is none yet. A separate "Acknowledge and resume anyway" with a typed reason (at least 10 visible characters; control and format characters such as zero-width or bidi are refused) is recorded with the request, and the coordinator then resumes at its next look, recording who, why and what main was in `merge.resumed`. The coordinator acts only on a request a person made on the dashboard whose login is an owner of the repo when it acts, with a reason that passes the same check; any other request is logged as ignored (`merge.resume_ignored`) and resumes nothing. **No synchronous resume:** auto-merge resumes at the coordinator's next look, not when you click. Deleting `auto-merge-stopped.json` by hand no longer resumes it either while main isn't green: the coordinator writes the stop back (`merge.stopped` with `restored`). What changes on upgrade:
  - **No `required_checks` configured means main is never measured green,** so such a stop waits until you acknowledge it on the dashboard (before, a resume never looked at main).
  - A stop already in force from an older engine has no `by` recorded and is treated as one the default branch caused: it waits the same way, and the coordinator answers its resume request by the stop file itself when no stop of its own is logged.
  - Any other stop (`by: owner`) resumes as before.
  - A red-main stop now has its own banner on every page (`auto-merge-stopped`), with the same resume and acknowledgement as the main watch's alert; before, only the main watch's stop had a button.
