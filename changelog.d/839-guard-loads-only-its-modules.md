### Guardrail changes: what each one does

- **The agents' tool guard loads 57 modules, down from 83, and only those are locked as the guard (#785).** The read-only lanes' rules it decides with (the research, intake and chat runs' tools, refusals and deny lists) moved into its own modules, `src/guard/**`, locked as a folder. The guard no longer loads `src/research.ts`, `src/intake/*` or the agent runner's modules. Its decisions are unchanged, call for call, on a corpus of 111 tool calls. **Loosening, as issue #785 asks (the owner's decision 7 of the review.yaml narrowing, 2026-10-18):** 9 modules that were locked only because the guard loaded them are ordinary engine code again, and get the review their own paths call for (in the engine's own repo, that is still the owner's while its `review.yaml` lists `engine: [src/**]` at L3): three `src/intake/` modules the guard used to reach (`addressing`, `discord-gate`, `discord`), `src/claude-auth-failure.ts`, `src/local-day.ts`, `src/locks.ts`, `src/run-feed.ts`, `src/run-record.ts` and `src/usage-limit.ts`. The modules that left the tree but still decide what an agent run gets stay locked, now under a part of their own, "what an agent run is given": the agent settings, context bundles, host requests, the stuck-run stop, the MCP and plugin modules the guard used to reach, the intake run's output schema and draft checks (`src/intake/triage.ts`), and the research, intake, chat, replier, explainer and stage-judge run builders (`src/research.ts`, `src/intake/run.ts`, `src/intake/chat.ts`, `src/intake/replier.ts`, `src/intake/explain.ts`, `src/stage-label.ts`), which set the role, lane and tools of runs that read untrusted text (#841 proposes moving that choice into locked code, which would let those six go). `src/events/redact.ts` stays locked too, under sign-in, credentials or secrets, and the intake's trust checks (`src/intake/report.ts`) and its candidate bound (`src/intake/dedupe.ts`, which issues the intake agent may name) under who may approve.
