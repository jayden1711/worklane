### Guardrail changes: what each one does

- **A child process the engine starts never gets a variable from `Object.prototype` (#846).** Node copies an env object's inherited keys into a child's environment, and it does the same with no `env` at all. So code in the engine's process that set `Object.prototype.NODE_OPTIONS` (or `GIT_CONFIG_*`, `PERL5OPT`, `HTTPS_PROXY`, ...) reached every child: git, perl, node, the agents' runs and the rest. The same went for the setup check's worker thread (the dashboard's first-run page), which took `Object.prototype.env` as its whole environment, and its children with it: `gh`, `claude` and the service manager. Now every process and worker the engine starts goes through one module (`src/os/child-process.ts`), which gives it a null-prototype copy of only the variables that are set. Nothing changes when the prototype is clean. The module joins the agents' tool guard's locked tree, since the guard's OS adapter starts processes through it, which takes the tree to 60 modules.
