### Upgrading (from v0.5.2)

- **Git hooks, launchers, state files, task files and server init's record are never written through a link planted beside them (#1062, after #950).** `writeExecutable` wrote through the guessable `<file>.<pid>.tmp` and set its mode by name; `writeGroupOnly` and `writeAgentReadable` wrote in place, following a link at the name they were given, and set the group and mode by name; and server `init` opened its record to the coordinator's group by name after writing it. Each now writes as owner-only files do since #950: a new file at a random hidden name beside it, `.<name>.<16 hex>.new`, created exclusively without following a link, with its group, its mode and its data set through that one open file, then renamed into place. A staging file found replaced before the rename is refused and removed, and the old file is left as it was. Server init's record gets the coordinator's group and 0640 before it is published, or stays 0600 when the group can't be given. Modes are unchanged: a state file is 0660, or 0600 when the file it replaces is 0600 or the umask leaves a new one 0600. Two things differ: a state file or task file is now replaced (a new file, this user's) rather than rewritten in place, and a process killed mid-write may leave a `.new` file beside the file; `export` leaves it out of a bundle, as a temporary file.
