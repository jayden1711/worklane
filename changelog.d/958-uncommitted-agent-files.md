### Guardrail changes: what each one does

- **An agent run doesn't start when what Claude Code loads from the checkout isn't what its last commit holds (#958).** A project command (a worktree setup step, a dependency's install script) runs as the agent user and could write `.claude/settings.json` with a `SessionStart` hook, or a `CLAUDE.md`, into the checkout. The next agent run loaded it and ran the hook outside any sandbox, because project hooks were allowed ("they only add"). Now anything under `.claude/` (a gitignored file there included, never the coordinator's own `.claude/worktrees/`) and any `CLAUDE.md` or `CLAUDE.local.md` that differs from the checkout's HEAD, or isn't in it, refuses the run, naming the files. So does a `.claude` that is a link or not a folder, or a link under `.claude/` (git never looks inside a linked folder). And the `CLAUDE.md`, `CLAUDE.local.md` and `.claude/CLAUDE.md` that Claude Code loads up front, from the top down to the run's folder, are compared with HEAD byte for byte, whatever the ignore rules say, so a `.gitignore` the same step writes can't hide one. An empty, untracked file (the mount points Claude Code's sandbox leaves on Linux) doesn't count. A checkout whose status can't be read refuses too. Not covered: an ignored `CLAUDE.md` deeper in the tree, as under `node_modules`.
