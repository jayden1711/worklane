### Guardrail changes: what each one does

- **A guarded agent run loads nothing from its checkout (#958, the owner's decision).** A project command (a worktree setup step, a dependency's install script) runs as the agent user and could write `.claude/settings.json` with a `SessionStart` hook, or a `CLAUDE.md`, into the checkout; the next agent run loaded it and ran the hook outside any sandbox, because project hooks were allowed ("they only add"). A guarded run (an instance's agent settings) now starts Claude Code with `--setting-sources ''`, as planner runs already did: no project, local or user settings, hooks or `CLAUDE.md` (a parent folder's included) reach it, and its settings are the instance's own (`--settings`). Project permission rules and hooks no longer apply to guarded runs. CI proves it on the real `claude` at the version the machine installs (`scripts/ci/setting-sources-probe.mjs`): a hook in each settings file, an MCP server, `CLAUDE.md` in the checkout, `.claude/`, `CLAUDE.local.md`, a parent folder and the agent's home, a rules file, a skill, an agent and a command reach no request and run nothing, while the same files do reach an unguarded run.
