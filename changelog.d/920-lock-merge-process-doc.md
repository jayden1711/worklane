### Upgrading (from v0.5.2)

- **The planners' decisions index fails closed.** A decision record (a decisions file, or an entry in a decisions folder) that is a symlink is indexed only when its real path is itself a decision record path inside the checkout: a link out of the checkout, or to any other file (`decisions.md -> notes.md`), is no longer indexed, so a plan can't cite it. And when the checkout has a `docs/process.md` that can't be read (for example a symlink loop, or a folder the engine can't search), no decision record is indexed: plans can still cite the decisions already made. A managed app that kept a record behind such a link moves the text to the record's own path, or plans citing it are refused.

### Guardrail changes: what each one does

- **The engine repo's merge process waits for the owner.** In the engine's own repo, a change to `docs/process.md` (how the repo's own PRs are merged and reviewed) is now self-modification: L3, and never auto-merged, whatever `review.yaml` says. The engine's own `review.yaml` also holds it under `engine-guards`. A managed app's file of the same name keeps the categories its own `review.yaml` gives it.
- **The page is kept out of the planners' decisions index, in two ways.** The index code leaves out a decision record that is the checkout's `docs/process.md` under another name (a symlink or a hard link to it), and any record whose real path isn't a decision record path inside the checkout. That code can't recognise a copy of the page's text. So, in the engine's own repo, every decision record path (`decisions.md`, `DECISIONS.md`, `docs/decisions.md`, `docs/DECISIONS.md`, `.worklane/decisions.md`, `docs/design.md`, and the folders `decisions`, `docs/decisions`, `docs/adr` and `.worklane/decisions` with everything in them) and the index code (`src/plan-decisions.ts`) are now self-modification too, and listed under `engine-guards`: a PR that adds or changes a decision record, a copy of the page whole, in part or reworded included, waits like the page itself. The lock reads the index's own lists, so a path the index reads is locked by the same change. `test/plan-decisions.test.ts` is locked the same way. A managed app's decision records keep the categories its own `review.yaml` gives them.
