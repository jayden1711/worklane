### Guardrail changes: what each one does

- **The test-run helper's GPU line counts only the wait for the lock (#968).** `waited <s> s` in `worklane-testrun: gpu <N> (...)` is now the time spent in `flock` alone, summed over the run's GPUs. Before, it also counted the lock files' setup (their owner, group and mode checks), so a slow machine could report a wait on a lock nobody held. The wait still counts against the run's timeout as before, and the unit still gets what is left.
- **An experiment job's record counts only the wait for the GPU lock too (#968).** The experiments helper's `waited_s` is the time spent in `flock` alone, summed over the job's GPUs, never the lock files' setup; its GPU lock functions stay the test-run helper's own.
- **A GPU tier that timed out names the cap that stopped it (#968).** The check says "the GPU runs' max_minutes in root's testrun-gpu.json" only when the unit's max was root's `max_minutes`; a unit that got what was left of the tier's `timeout_s` names that, however long the helper took before the lock. When the coordinator can't read root's file, it decides as before.
