### Upgrading (from v0.5.2)

- **Test-run tiers that wait on `pgrep -f` or `ps … | grep` in a loop are no longer run (#1172).** A tier command like `until ! pgrep -f trainer; do sleep 5; done` runs under `sh -c "<command>"`, whose own command line holds the pattern, so the wait matches its own shell and never ends: before, it ran until the tier's `timeout_s`. Now the tier fails at once, unrun, saying why and what to wait on instead (a pidfile, a lock, or `pgrep -x <exact name>`). A one-off `pgrep -f` check, and a loop on `pgrep -x`, still run. Change any such tier in `tests.yaml` before the update.
- **A head whose fast test run was cut off twice is not run again by itself (#1172).** A run the coordinator didn't finish (a crash, a power cycle after the machine hung) is still run again once at the next start. A second cut-off at the same head now gets its PRs a failing check (`cut off 2 times …: not rerun automatically`), and a new push runs it again. GPU runs are unchanged: never run again after one cut-off.
- **A GPU tier that loses its GPU is a stopped GPU run (#1172).** When a GPU command fails and its output shows the device gone ("No devices were found", Xid 79, "GPU has fallen off the bus"), the run is never run again by itself, a batch holding it is held, and the run's later GPU tiers aren't run. Before, it was an ordinary failure.
