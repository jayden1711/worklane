### Guardrail changes: what each one does

- **Setup's login proof loads nothing either (#1262, #958).** `scripts/setup/lib.sh`'s one real call that proves an agent user's Claude login (`claude -p "Reply with the single word: ok" ...`) ran with every setting source, so a hook or `CLAUDE.md` in that user's home loaded with it. It now ends with the engine launch's guards (`--settings '{}' --setting-sources '' --strict-mcp-config`), keeps Claude's auto memory off, and runs in an empty folder that user makes for it, removed after (only a folder `mktemp` made under `/tmp`).
- **A lint holds the repo's scripts to the same rule (#1262, the owner's decision).** `test/claude-launch-shell-lint.test.ts` reads every shell script, workflow step and script in `scripts/`. Any `claude` one starts must end with those guards, or be a pinned exception: `--version`, `auth status`, `auth login`, and a CI probe of Claude Code's own MCP policy. It reads a direct call, `command`/`exec`, `env`/`sudo`/`timeout`/`nice` wrappers, a variable set to claude, `$(...)`, backticks, `sh -c`, a heredoc fed to a shell, an array of arguments, and a JavaScript literal call. Its limits (`eval`, a name built from parts, a wrapper function, a variable from elsewhere) are named in the test.
