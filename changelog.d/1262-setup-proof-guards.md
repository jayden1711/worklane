### Guardrail changes: what each one does

- **Scripts start Claude through one launcher (#1262, #958).** `scripts/setup/lib.sh` has `claude_guarded`, the one way a setup, CI or spike script starts a Claude session. It runs claude in an empty environment (its home, a fixed `PATH`, auto memory off, and only a few named settings such as `CLAUDE_CONFIG_DIR`), so nothing like `CLAUDE_CODE_PLUGIN_DIRS` or `NODE_OPTIONS` reaches it. It runs in a clean shell, so no shell function of the caller's can change what it runs. Its words must start with `-p`, so no word is taken as a Claude subcommand, and it lets through only flags on an allowlist (`-p`, `--model`, `--max-turns`, `--output-format`, `--allowedTools`, `--permission-mode dontAsk`, `--input-format text`, …), each value-taking one with its value, so a plugin, agents, an added directory, an MCP config or stream-json control requests can't be passed in any spelling. It takes `--settings` only as `{}` or an API-key login's `apiKeyHelper` reading a plain absolute path, and it ends every call with the engine launch's guards (`--settings <json> --setting-sources '' --strict-mcp-config`).
- **Setup's login proof loads nothing.** Its one real call that proves an agent user's Claude login now goes through `claude_guarded`, in an empty folder that user makes for it (removed after). An API-key login's key reaches claude only through `apiKeyHelper`, built by a JSON encoder after the key path is checked again.
- **A lint holds the repo's scripts to it (#1262, the owner's decision).** `test/claude-launch-shell-lint.test.ts` fails closed. In every shell script (by extension or shebang, anywhere, `.githooks/` included), workflow and composite-action step, Makefile recipe, `package.json` script, Dockerfile `RUN` line, and JavaScript or TypeScript file under `scripts/`, any word that is the claude binary (its name, a path, a lookup like `"$(command -v claude)"`, its npm package or its `cli.js`) is a call, whatever launches it, unless a known non-launcher (`install`, `rm`, `command -v`, `echo`, …) holds it as data. Any call other than through `claude_guarded` is refused, unless it starts no session (`--version`, `auth status`, `auth login`) or is pinned: four exceptions (`claude_guarded`'s own launch, a CI probe of Claude's MCP policy and two `credentials.sh probe claude` steps) and two spikes (four calls), each held with the digest of its function or step and of every assignment its call reads. Its limits are named in the test.
